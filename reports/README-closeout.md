# KNS Transport | ระบบสรุปจบงาน

เปิดหน้า `reports/closeout.html` จากปุ่ม **สรุปจบงาน / รีพอร์ตรายสัปดาห์** ในหน้าแผนหลัก

## วิธีใช้งานประจำวัน

1. ในหน้า STP, PTR หรือ ส่งออก เลือกวันที่และกด **บริษัท / ปัญหาแบช** ประจำคัน เลือกชื่อบริษัทขนส่งจากดรอปดาวน์ **KNS / มีโชค / จิรภัทร** หรือกด **เพิ่มชื่อบริษัทขนส่ง** เพื่อบันทึกตัวเลือกใหม่ที่ใช้งานได้ทั้งเว็บ แล้วระบุประเภทปัญหาแบช (ไม่มี / เล็ก / ใหญ่ / ทั้งสอง) และรายละเอียด
2. กด **ตรงแผน / ไม่ตรงแผน** ให้แต่ละคันในหน้าแผนตามปกติ
3. กด **สรุปจบงาน / รีพอร์ตรายสัปดาห์** เพื่อเปิดรายงานของวันที่เลือก
4. ตรวจสอบจำนวนคัน: นับจาก (หน้าแผน + Booking ถ้าเป็นส่งออก + เลขคัน) ไม่ใช่จำนวนแถวสินค้า; ชื่อบริษัทและปัญหาแบชจะแสดงจากแผน
5. เพิ่มหมายเหตุภาพรวม ตรวจสอบสถานะ และกด **บันทึกจบงานวันนี้** เพื่อบันทึก snapshot ลง Firebase
6. หากมีฟีดแบ็คทีหลัง เลือกวันที่เดิม เปิดรีพอร์ต แล้วแก้คอลัมน์ **ฟีดแบ็คภายหลัง / การแก้ไข** ก่อนบันทึกอีกครั้ง ระบบเพิ่มเลข revision และเก็บผลใหม่ในรายงานเดียวกัน ไม่สร้างรายงานซ้ำ
7. เลือกวันในสัปดาห์ กด **รวบรวมรีพอร์ตสัปดาห์** ตรวจวันที่ยังไม่มีรายงาน จากนั้นกด **บันทึกรีพอร์ตสัปดาห์** หรือดาวน์โหลด Excel

## ขอบเขตการคำนวณ

- ตัวเลขไม่ตรงแผนนับ 1 ต่อคัน/ตู้ที่ไม่ซ้ำกันในแต่ละหน้า แม้มีหลายสินค้า
- เลขคันเดียวกันของ STP, PTR หรือ Booking ส่งออกคนละชุด นับแยก
- ปัญหาแบชเล็กและแบชใหญ่เป็น **จำนวนคันที่มีปัญหาประเภทนั้น** (ถ้าระบุทั้งสองประเภท คันเดียวอาจถูกนับในทั้งสองหมวด)
- นับสถานะ `pending` เป็นรายการที่ยังไม่ระบุ ไม่จัดเข้าตรงแผนโดยอัตโนมัติ
- รีพอร์ตรายสัปดาห์ใช้เฉพาะรายวันที่ **บันทึกจบงานแล้ว** วันอื่นแสดงว่ายังไม่มีรีพอร์ต ไม่แสดงเป็น 0 คัน
- แก้ข้อมูลในหน้า closeout แล้วจะเปลี่ยนข้อมูล **รายงาน** เท่านั้น ไม่เขียนทับตารางแผนต้นฉบับ เพื่อรักษาหลักฐานย้อนหลัง
- วันที่เริ่มและจบสัปดาห์คือจันทร์–อาทิตย์
- รีพอร์ตรายวัน/สัปดาห์เปิดกลับมาแก้ไขได้; revision เก็บเพียงเลขครั้งแก้และ snapshot ล่าสุด **ไม่ใช่ระบบเก็บทุก revision แยกฉบับ**
- หากมีการเปลี่ยนรายวันหลังสร้างรีพอร์ตสัปดาห์แล้ว ต้องกด **รวบรวมรีพอร์ตสัปดาห์** อีกครั้ง แล้วบันทึกสัปดาห์ฉบับใหม่

## ที่เก็บข้อมูลใน Realtime Database

- `knsTransport/pages/{STP|PTR|OUT}/plans/{yyyy-mm-dd}/rows`: แผนและข้อมูลบริษัทขนส่ง / ปัญหาแบชรายคัน (บันทึกลงทุกแถวของคัน)
- `knsTransport/reports/closeouts/{yyyy-mm-dd}`: รายงานสรุปประจำวัน, ชุดรายการคัน, ฟีดแบ็ค และเลขแก้ไข
- `knsTransport/reports/weeklyCloseouts/{monday-yyyy-mm-dd}`: snapshot รายสัปดาห์
- ใช้ `reports/config.js` ร่วมกับหน้ารีพอร์ตเดิม

## การติดตั้งและความปลอดภัย

ต้องเผยแพร่ไฟล์ `reports/closeout.html`, `reports/closeout-app.js`, `reports/closeout-core.js` และไฟล์ `reports/config.js` / `reports/audit.js` ไปกับเว็บไซต์ (เพียงอัปเดต GitHub **ไม่ได้หมายความว่า Firebase Hosting จะเผยแพร่แล้ว**).

ระบบบันทึกข้อมูลขึ้น Realtime Database ด้วยบัญชี/กฎการเข้าถึงที่ตั้งไว้ในโปรเจกต์เดิม ตรวจสอบ Firebase Database Rules ก่อนใช้งานกับข้อมูลจริง; โค้ดนี้ไม่ได้เพิ่มระบบ Login หรือเปลี่ยน Rules ให้โดยอัตโนมัติ. การส่งออก Excel ใช้ไลบรารี SheetJS ผ่าน CDN และต้องใช้อินเทอร์เน็ตเพื่อโหลดไลบรารีนี้

ทดสอบตัวคำนวณจากเครื่องที่มี Node.js:
```bash
node --test reports/closeout-core.test.mjs
```

## ระบบบันทึกเหตุการณ์แบชอัตโนมัติ

- แก้ **Batch No.** จากหน้าต่างแก้ไขข้อมูลทั้งแถว → บันทึกเหตุการณ์ `batch_edited` พร้อมค่าเดิมและค่าใหม่, วันแผน, หน้า STP/PTR/ส่งออก, คัน, Booking และสินค้า
- กด **+ รายการ** เพื่อเพิ่มแถวสินค้าในคันเดิมโดยตรง → บันทึก `manual_item_added` ทันที แม้ยังไม่ได้กรอกเลขแบช จากนั้นเมื่อเลขแบชถูกกรอก/แก้ต่อก็จะบันทึกอีกเหตุการณ์ตามจริง
- เพิ่มคันใหม่, คัดลอกรายการ, คัดลอกวันก่อน และนำเข้าไฟล์ ไม่ได้ถูกเหมารวมว่าเป็นเหตุการณ์แก้แบชด้วยมือ
- กิจกรรมทั้งหมดเก็บใน `knsTransport/reports/batchChanges/{planDate}/{eventId}` ในคำสั่งบันทึกเดียวกับข้อมูลที่แก้ (ถ้าบันทึกข้อมูลล้มเหลวจะไม่เกิดเหตุการณ์หลอก)
- หน้าสรุปจบงานแสดงรายการอัตโนมัติและให้เลือกว่า **รอตรวจสอบ / ยืนยันเป็นปัญหา / งานปกติ**; ระบบไม่เดาเองว่าแบชเล็ก/ใหญ่หรือว่าเป็นความผิดพลาดทุกครั้ง
- รายสัปดาห์แสดงเหตุการณ์ทั้งหมดในช่วงนั้น พร้อมส่งออกเป็นชีท **Batch Changes** ในไฟล์ Excel
- เหตุการณ์บันทึกย้อนหลังมีเฉพาะการแก้ไข **หลังติดตั้งรุ่นนี้** ไม่สร้างจากข้อมูลในอดีตโดยเดาเอา

## รายงานเที่ยวรถตามบริษัท (รายสัปดาห์ / รายเดือน / รายปี)

ในหน้า `reports/closeout.html` ส่วน **เที่ยวรถแยกตามบริษัทขนส่ง** เลือกช่วงเวลาและวันที่อ้างอิง แล้วกด **สรุปเที่ยวตามขนส่ง**. ระบบดึงข้อมูลจากรีพอร์ตจบงานรายวันที่บันทึกแล้วเฉพาะช่วงที่เลือกและนับตามคัน/ตู้ในรีพอร์ต:

- **วิ่งแล้ว** = สถานะตรงแผน + ไม่ตรงแผน
- **เลื่อน** และ **ยังไม่ระบุ** แสดงแยก ไม่ปนกับจำนวนที่วิ่งแล้ว
- แสดงการนับแยก **STP / PTR / ส่งออก** ต่อบริษัท
- รายงานที่ไม่ได้ปิดงาน **ยังไม่ถูกนับ**; ถ้าวันใดยังไม่มีรีพอร์ต ระบบจะไม่อนุมานว่ามี 0 คัน
- สามารถดาวน์โหลด Excel ซึ่งมีสรุปแยกบริษัทและรายละเอียดทุกคัน
- แก้รายงานรายวันย้อนหลังแล้วกด **สรุปเที่ยวตามขนส่ง** อีกครั้งเพื่ออัปเดตยอด

บริษัทขนส่งอื่น ๆ เพิ่มและบันทึกได้ใน `knsTransport/settings/transportCompanies`.
